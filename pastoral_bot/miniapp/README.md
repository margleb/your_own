# Православный помощник — Telegram Mini App

Frontend использует тот же изолированный сервис и состояние пользователя, что и бот. Обычная история приходит из API; подготовка к исповеди, черновик сообщения, заметка и подписанные данные Telegram существуют только в памяти приложения. Local/session storage, аналитики и внешних шрифтов нет.

```sh
npm ci
npm run build
npm test
```

Node.js 22.12+; lockfile фиксирует зависимости. `dist/` — статический результат сборки. `base: './'` и относительные `api/...` позволяют обслуживать приложение по `/pastoral/` с удалением этого префикса в reverse proxy.

API требует `Authorization: tma <Telegram.WebApp.initData>` для каждого запроса. В обычном браузере приложение показывает публичную главную страницу и ссылку на бота; обхода авторизации или демонстрационных ответов нет. После изменения режима/темы/удаления результаты старой `epoch` отбрасываются; сетевой повтор незавершённого сообщения использует прежний UUID.

Для визуальных проверок вне Telegram нужен отдельный локальный сервер с тестовым SDK и подписанным тестовым launch data. Он не входит в production-сборку. Изменять приложение ради такого обхода нельзя.
